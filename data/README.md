# City and local cultural places

`landmarks.json.gz` is the complete Wikidata CC0 snapshot, retained losslessly with gzip compression in source for audit and regeneration. Read with `gzip.open()` in Python or `gunzipSync()` in Node. It is intentionally outside `public/`: the uncompressed export exceeds the host's 25 MiB single-file limit. The website loads the compact index at `public/data/landmarks-index.json` and generates shared display fields in the client.

Refresh public query exports with `python3 scripts/download-landmarks.py` (or `--only china-local global-museums global-places`), then run `python3 scripts/prepare-landmarks.py` and `node scripts/prepare-landmark-regions.mjs`. The pipeline preserves existing records, original item URLs, country memberships, data classes and coordinates. Query batch limits are recorded in the coverage manifest; this is a sourced selection, not a complete or live directory of every attraction.

Wikidata structured data is CC0. Image rights remain with their Wikimedia Commons authors; Wikipedia summaries are fetched with an attribution link and the CC BY-SA notice. The tests compare the full snapshot and compact index, check administrative containment, and verify deduplication and coverage counts. The build also checks the hosting asset-size limit.

For a China-focused update, download the four `china-zero`, `china-heritage-gaps`, `china-nature-local` and `china-scenic` batches, then run `python3 scripts/prepare-landmarks.py --china-only --extra china-zero china-heritage-gaps china-nature-local china-scenic` before rebuilding the region index. `china-expansion-baseline.json` records the comparison commit and regional counts. The region pipeline considers every polygon component and falls back to detailed city boundaries for small islands omitted by province overviews. Source ISO country codes are preserved; the Chinese province explorer also groups Taiwan entries under its province entry.
